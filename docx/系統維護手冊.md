# 2026 宇宙科技公司員工旅遊報名系統維護手冊

> 文件用途：記錄目前系統架構、部署位置、資料流程與維護程序。  
> 適用對象：網站維護人員、活動承辦人、Google Workspace 管理人員。  
> 最後更新：2026-10-30

## 1. 系統概覽

本系統是員工旅遊活動的靜態報名網站。網站由 GitHub Pages 提供，表單透過 Google Apps Script Web App 將報名資料寫入 Google 試算表。

| 元件 | 用途 | 目前位置 |
|---|---|---|
| 靜態網站 | 活動介紹、輪播圖片、報名表單 | [GitHub Pages](https://d19070503-blip.github.io/2026-company-travel/) |
| 原始碼 | 網站、Apps Script 程式及文件 | [GitHub repository](https://github.com/d19070503-blip/2026-company-travel) |
| Apps Script Web App | 接收報名資料並寫入試算表 | [Web App](https://script.google.com/macros/s/AKfycbzNG4BmUl_JVWMVLLbvMRF_UcgiXw9gHOvr0P1ESIiPJdMO_SylPQxUcWOeX2FsNteI/exec) |
| Google 試算表 | 保存報名記錄 | [2026_公司旅遊](https://docs.google.com/spreadsheets/d/1ZFIbTYDn7snTXsW6-5GyAQwfCvd4J7BEgAADDcV58gU/edit) |

### 資料流程

```text
瀏覽者填寫表單
       │
       ▼
GitHub Pages（index.html + script.js）
       │ HTTPS POST，JSON 字串，no-cors
       ▼
Google Apps Script Web App（Code.gs）
       │ SpreadsheetApp.openById()
       ▼
Google 試算表：2026_公司旅遊
```

前端送出使用 `mode: 'no-cors'`，以避免瀏覽器對跨來源 JSON 請求的 preflight 限制。此模式會回傳 opaque response，前端無法讀取 Apps Script 的成功／失敗內容。頁面因此會告知「請確認試算表」，不能僅依前端訊息認定資料已成功寫入。

## 4. 試算表資料結構

檔案名稱及工作表名稱皆為 `2026_公司旅遊`。第一列由 Apps Script 設定為標題列：

| 欄位順序 | 標題 | 前端欄位鍵 | 格式／說明 |
|---:|---|---|---|
| A | 姓名 | `name` | 文字 |
| B | Email | `email` | 文字 |
| C | 所屬單位 | `department` | 文字，可空白 |
| D | 手機 | `phone` | 純文字格式，保留前導 0 |
| E | 職稱 | `title` | 文字，可空白 |

`Code.gs` 會在每次寫入時檢查或建立指定工作表、確保標題列，並將 D 欄及新寫入的手機儲存格格式設為文字 (`@`)。

## 5. Apps Script 與存取設定

- 專案編輯器：[Apps Script 專案](https://script.google.com/home/projects/14dwQ1uoQ-wfHph5B_W7Kj6OwYgiqZZWCc3RzIxnrSTY4a-QXNtqLWmqM/edit)
- Web App 部署網址：見「系統概覽」。
- 部署身分：擁有者（執行者為我）。
- 存取權：所有人（匿名皆可呼叫）。
- Script 會以固定試算表 ID 開啟 `2026_公司旅遊`；執行部署的 Google 帳號必須仍有該試算表編輯權限。
- `doGet()` 僅提供健康檢查回應；`doPost(e)` 接收 JSON 文字並寫入資料。

### 更新 Apps Script

1. 在 Apps Script 編輯器更新 `Code.gs`。
2. 儲存並執行適當函式，首次存取試算表時完成 Google 權限授權。
3. 選「部署」→「管理部署作業」→編輯目前 Web App 部署。
4. 選擇建立新版本並更新部署。
5. 確認部署仍設定為「執行者：我」及「誰可以存取：所有人」。
6. 若 Web App URL 改變，更新 `script.js` 的 `appsScriptEndpoint`，並重新部署網站。
7. 從網站送出一筆測試資料，再到試算表確認資料與手機格式。

不要只儲存 Apps Script 程式碼而忘記更新部署版本；Web App 可能仍執行先前已部署的版本。

## 6. 本機開發與網站部署

### 本機預覽

在專案根目錄執行：

```powershell
python -m http.server 8000
```

瀏覽 `http://localhost:8000`。停止伺服器可在終端機按 `Ctrl+C`。

### 發佈到 GitHub Pages

1. 修改並檢查 `index.html`、`styles.css`、`script.js` 或圖片。
2. 確認 `spec/` 未納入提交。
3. 執行 `node --check script.js` 與 `git diff --check`。
4. 提交並推送至 `master` 分支。
5. 等待 GitHub Pages build 狀態完成，再開啟正式網址確認更新。
6. 若瀏覽器仍顯示舊 JavaScript，更新 `index.html` 的 script query version，例如 `script.js?v=20261030-2`，以失效快取。

## 8. 故障排除

| 現象 | 檢查方式 | 處理方式 |
|---|---|---|
| 表單提示需確認試算表 | 查看 `2026_公司旅遊` 是否新增列；查看 Apps Script「執行項目」是否有錯誤 | 確認 Web App 部署存取權、部署帳號的試算表權限與最新部署版本 |
| 手機開頭的 0 消失 | 檢查 D 欄及該儲存格格式 | 執行 `ensureSheet()`，確認 `Code.gs` 設定 `@`，必要時將既有欄轉為純文字 |
| Apps Script URL 回報找不到 `doGet` | 開啟的 Web App 可能仍連到舊專案或舊部署 | 確認正確專案有 `doGet()`，儲存並更新部署 |
| 網站更新後仍執行舊程式 | 瀏覽器或 CDN 快取 | 使用強制重新整理；變更 `index.html` 中的 query version 並重新發布 |
| 表單資料未送出 | 檢查瀏覽器 Console、網路連線及 Apps Script 執行記錄 | 確認 endpoint 可開啟、沒有授權錯誤，並核對 Apps Script 使用的試算表 ID |
| 同一人資料重複 | 檢查是否多次按送出或因不確定而重試 | 前端會在請求期間停用按鈕；提交結果需以試算表核對。若要強化去重，需新增伺服端唯一識別與重複規則 |

## 9. 安全與隱私注意事項

- 報名資料含姓名、Email、手機等個人資料；只授權必要的試算表管理者存取，並依組織政策設定保存期限。
- Web App 的匿名公開存取是為了讓公開的 GitHub Pages 表單可呼叫；任何人都可能嘗試呼叫此 endpoint。若活動資料需限制對象，應加入伺服端身份驗證或改用受控平台，不能只在前端隱藏表單。
- 不要將 Google OAuth token、服務帳戶私鑰或其他登入憑證寫進網站原始碼或 Git。
- Apps Script 使用部署者權限寫入試算表；若部署者帳號或試算表權限變更，表單寫入可能中斷。
- `no-cors` 模式不提供可讀取的伺服端回應，因此前端無法可靠判斷資料是否入表。若需要明確成功／失敗回饋，應改設支援 CORS 的後端代理服務或採用其他具驗證及回應能力的架構。
